## 错误预算消耗率告警规则

| 告警名 | 规则 | 含义 |
|--------|------|------|
| `SLOBurnRateCritical` | 1h 消耗率 > 14.4x | 按此速度 2 小时耗尽全月预算，立即处理 |
| `SLOBurnRateHigh` | 6h 消耗率 > 6x | 按此速度 5 小时耗尽全月预算，1 小时内处理 |
| `SLOBurnRateMedium` | 1d 消耗率 > 3x | 按此速度 10 天耗尽全月预算，工作时间处理 |
| `SLOBurnRateLow` | 3d 消耗率 > 1x | 预算消耗过快，纳入下次迭代优化 |

## 变更冻结与错误预算联动

| 错误预算剩余 | 变更策略 |
|-------------|---------|
| > 50% | 正常发布 |
| 20% - 50% | 需要额外审批，禁止高风险变更 |
| 5% - 20% | 仅允许 hotfix，变更需 TL 审批 |
| < 5% | 冻结所有非紧急变更，专注可靠性改善 |

## SLI 计算方式

**可用性 SLI**
```
good_requests / total_requests

其中 good_requests = 状态码非 5xx 的请求数
```

**延迟 SLI**
```
requests_within_threshold / total_requests

其中 requests_within_threshold = 响应时间 < 阈值的请求数
```

**消息投递成功率 SLI**
```
successfully_delivered / total_attempted

其中 successfully_delivered = 在 5 分钟内确认投递成功的消息数
```

## Prometheus 查询参考

```promql
# API 网关 30 天可用性
1 - (
  sum(increase(nginx_http_requests_total{status=~"5.."}[30d]))
  /
  sum(increase(nginx_http_requests_total[30d]))
)

# 当前错误预算剩余（以 API 网关 99.9% SLO 为例）
(
  (1 - 0.999) * sum(increase(nginx_http_requests_total[30d]))
  - sum(increase(nginx_http_requests_total{status=~"5.."}[30d]))
) / (
  (1 - 0.999) * sum(increase(nginx_http_requests_total[30d]))
)
```

## 注意事项

1. SLO 统计不包含计划内维护窗口（需提前在系统内申报）。
2. 依赖方故障（如云厂商中断）纳入计算，但可在月报中单独说明。
3. 每月 5 日前各服务负责人确认上月 SLO 达成情况，填写月报模板。
4. SLO 调整需经过平台可靠性组和业务负责人共同确认，走 RFC 流程。
